# 缓存与 DMA 共享数据协议草案

状态：规划。当前平台尚无自有 DMA 或缓存一致性互联。

需要分别回答：CPU 写的数据何时可供加速器读取；加速器写回后 CPU 如何看到
新结果；任务运行期间谁可以修改缓冲；完成通知前哪些写入必须已经生效。

首版可规划一段明确不经过所有相关缓存层的共享区域，并约定对齐、数据所有权
与同步顺序。该区域需要实际硬件解码支持，不能只在驱动中声明为不可缓存。

若采用缓存缓冲区，需要支持相应的写回/失效机制，并处理缓存行共享、脏行与
并发 CPU 访问。普通内存顺序屏障不能代替缓存写回和失效。
硬件一致性、专用 scratchpad 或显式数据拷贝可以作为后续方案分别评估。
